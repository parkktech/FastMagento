1 · Indexing Configuration

fastmagento/indexing/*  ·  Names the OpenSearch indexes FastMagento reads and writes. Most stores never change these.

Real-time vs. scheduled indexing is not set here. That's controlled by Magento's own System > Index Management ("Update on Save" / "Update by Schedule"), because FastMagento's indexers run off Magento's native mview.

Product Index Suffix

TextDefault: productsStore-level
fastmagento/indexing/opensearch_index_prefix

The suffix for FastMagento's product index. The full index name is the engine prefix joined to this suffix.

Resulting index name <catalog/search/opensearch_index_prefix>_<suffix> → e.g. magento2_products
Only change this to run parallel indexes (e.g. blue/green). After changing it, reindex so the new index is populated.

Category Index Suffix

TextDefault: categoriesStore-level
fastmagento/indexing/opensearch_category_index_prefix

Same idea for the category index that powers menus, breadcrumbs and layered-nav attributes.

Resulting index namemagento2_categories

2 · Instant Search & Relevance

fastmagento/search/*  ·  The knobs that decide which products a query returns and in what order. This is the section most stores need to understand — so it starts with how a query actually flows, then documents each control.

How one search query flows

1 · Clean
Lower-case, strip Stop Words
"the front end" → "front end"
2 · Expand
Add Synonym variants (equal weight)
+ "frontend", "sxs", "utv"
3 · Match
Per candidate: prefix + words + phrase, across weighted fields, with Operator & Typo rules
name^5 sku^6 …
4 · Boost
Phrase & all-terms boosts, then In-stock nudge
×4 phrase · ×1.6 in-stock
5 · Sort
By score, then your Custom Ranking tie-breaker
_score → bestseller
Mental model: stages 1–2 decide what counts as the query, stage 3 decides what matches, and stages 4–5 decide the order. When results feel wrong, find the stage responsible below.

Searchable Attributes & Weights

GridDefault: name·5, sku·6, short_description·1, description·1Store-level
fastmagento/search/searchable_attributes

Which product fields are searched, and how strongly each one counts. Higher weight = a hit there ranks higher. One place to control what Magento otherwise buries in each attribute's "Search Weight".

Leave it empty to use the built-in defaults. Add a row per attribute you want searched; the weight becomes the field boost (name^5) in every match clause.

Example name · 5   |   sku · 6   |   part_type · 3   |   description · 1
A query hitting the SKU or name outranks one that only appears in the description.
Attributes must be present in the search index. After changing this list, run indexer:reindex catalogsearch_fulltext.

Multi-Term Operator

SelectDefault: AnyStore-level
fastmagento/search/search_operator

How multiple typed words combine. This is the single biggest lever on "too many vs. too few results".

AnyOR — broadest. One matching word is enough. Most results, loosest. (default)
Most75% must match — balanced. A good middle ground for 3+ word queries.
AllAND — strictest. Every word must match. Fewest, most precise results.
Worked example — query "Frontend UTV" Any: returns anything that says frontend or UTV — so generic frontend parts leak in.
All: returns only products matching frontend and UTV — the intended UTV front-end parts.
Terms may be spread across name, keywords and description (cross-field) — "All" doesn't force every word into one field.

Typo Tolerance

Yes / NoDefault: YesStore-level
fastmagento/search/typo_tolerance

Fuzzy matching so misspellings still find results (the OpenSearch equivalent of Algolia typo tolerance).

Example"contol arm" → still finds "control arm"   ·   "suspention" → "suspension"
Applied to the as-you-type match with fuzziness: AUTO (edit distance scales with word length). Turn off only if fuzzy matches are pulling in noise on very short SKUs.

Exact / Phrase Match Boost

NumberDefault: 4Store-level
fastmagento/search/phrase_match_boost

How hard to rank products where the query appears as a contiguous phrase (in name / keywords) above products where the same words are just scattered around. 0 disables it.

Worked example — query "rock slider" A product named Rock Slider Kit (exact phrase) is boosted ×4 over one whose description happens to contain "rock" and "slider" in different sentences.
Higher (6–8)Exact phrasing wins harder — good when product names are clean and descriptive.
Lower (1–2)Softer — lets strong scattered-word matches compete.
0No phrase preference at all.
This value also feeds the "all-terms" precision boost (≈75% of it), so raising it tightens phrase and full-coverage ranking together.

Synonyms / Thesaurus

TextareaPre-populatedStore-level
fastmagento/search/synonyms

One equivalence group per line, comma-separated. A search for any term in a group also matches the others — and they're scored identically, so "frontend" and "front end" return the same results in the same order.

Format — one group per line sxs, utv
a-arm, a arm, control arm, control-arm
shock, damper, coilover
Keep terms distinctive. A group term that's a common catalogue word (e.g. "side" inside "side by side") over-broadens every query that expands to it, because synonym equivalents match at full strength. Put buyer phrases that contain common words into the AI Search Keywords layer instead — that's why sxs, utv lives here but "side by side" does not.
Multi-word terms work: substitution happens at the phrase level, so "a-arm" ⇄ "control arm" (joining/splitting words) is fine. Don't have a thesaurus yet? Generate one from your own catalogue — see AI Assistant.

Stop Words

TextareaPre-populatedStore-level
fastmagento/search/stopwords

Comma- or space-separated words ignored in queries, so filler doesn't dilute the match.

Defaulta, an, and, or, the, of, for, with, to, in, on, at, by, is, it, this, that, your, my
The raw multi-word phrase is preserved for phrase-matching even when a middle word is a stop word — so "side by side" stays intact rather than collapsing to "side side".

Facet Attributes

TextDefault: part_type, color, size, link_style, shock_spacingStore-level
fastmagento/search/facet_attributes

Comma-separated attribute codes that become the filter facets on the instant-search results page. Category is always included automatically.

Examplepart_type,compatible_platforms,color,size
Use filterable, SELECT-type attributes. Their option labels resolve cleanly from the index; multi-select attributes aren't supported here yet (they need an indexed option dictionary).

Boost In-Stock Products

Yes / NoDefault: YesStore-level
fastmagento/search/boost_in_stock

Nudges in-stock products above out-of-stock ones — without a hard sort, so text relevance stays primary.

Implemented as a ×1.6 score multiplier on in-stock items — a strongly-relevant out-of-stock product can still outrank a weakly-relevant in-stock one.

Custom Ranking Attribute & Direction

Text + SelectDefault: blank · Highest firstStore-level
fastmagento/search/custom_ranking_attribute  ·  …/custom_ranking_direction

An optional numeric attribute used as a secondary ranking signal, applied only after text relevance — Algolia-style custom ranking. Blank = relevance only.

Example custom_ranking_attribute = bestseller_score  ·  direction = Highest first
Products tie on text relevance → the higher bestseller_score wins.
DirectionMeaningGood for
Highest first (desc)Bigger value ranks higherbestseller rank, rating, popularity
Lowest first (asc)Smaller value ranks higherprice-low, "position" fields
Products missing the attribute sort last — they're never dropped from results.

AI Search Keywords Layer

Yes / NoDefault: NoStore-level
fastmagento/search/search_keywords_enabled

Turns on searching a hidden, AI-generated per-product keyword field (fm_search_keywords). It lets a product surface for terms its own copy never uses.

ExampleA UTV part with no "side-by-side" text in its description still ranks for side-by-side / SxS because those buyer terms were generated into its keyword field.
Two steps to go live: (1) populate the field off the request path with bin/magento fastmagento:search-keywords:generate, then (2) reindex catalogsearch_fulltext. Enabling the toggle alone does nothing until the field is populated.
Weightfastmagento/search/search_keywords_weight — how strongly keyword hits rank (default 8; name defaults to 5). Only used when the layer is on.
Source attrs…/keyword_source_attributes — attribute codes whose labels give the generator product context (e.g. part_type,make,model). Blank = reuse Facet Attributes. Global only

3 · AI Assistant

fastmagento/ai/*  ·  Global only   Connect an AI API key to auto-build a search thesaurus and keyword layer from your own catalogue. Entirely optional — leave the key blank to keep AI features off.

API Key

EncryptedDefault: blank (off)Global only
fastmagento/ai/claude_api_key

Stored encrypted. Used only by the generator tools below. Leave blank to disable all AI features.

Model & Max Catalogue Terms

TextDefault: model id · 1200 termsGlobal only
fastmagento/ai/claude_model  ·  fastmagento/ai/max_terms

Model — the model id to call. Max Catalogue Terms — an upper bound on how many attribute values + category names are sent to the model, so very large catalogues stay bounded and cost-controlled (default 1200).

Generate Thesaurus Action

ButtonGlobal only

Reads your attribute values + category names and builds shopper-facing synonym groups, merged into Search > Synonyms.

Order of operations: save the API Key first → click Generate → review the proposed groups → Save the Synonyms field. Nothing changes live search until you save.

4 · Fast Checkout

fastmagento/cart/*  ·  Serves cart & checkout line items from OpenSearch instead of the native ~217-query product collection — the biggest single win for configurable-heavy carts.

Enable Fast Checkout Master

Yes / NoDefault: Yes (ON)Store-level
fastmagento/cart/enable_fast_checkout

The one switch most stores use. On by default, it enables the whole fast pipeline — OS-served quote items, optimistic stock, and fast stock sync — so Fast Checkout works fully out of the box.

Cannot oversell. Order placement still re-checks salable quantity by SKU (MSI reservations); a truly out-of-stock order is rejected at placement. Any product missing/partial in the index falls back to the fully native path automatically.
After go-live, run a full reindex and place a test order to confirm totals. Set to No to fall back to the fully native cart.

Advanced toggles Granular

Yes / No ×3Default: No (implied by Master)Store-level

These three give granular control. They're hidden while the master is On (which already turns them on). Each can also force its feature on by itself when the master is Off.

os_serve_quote_itemsServe Quote Items from OpenSearch. Hydrate cart/checkout line products from the index instead of the ~217-query collection. Hard native fallback for missing/partial, custom-option, and bundle/grouped carts.
optimistic_stockOptimistic Stock. Skip the redundant per-load MySQL stock preload and rely on the authoritative placement-time gate. Trade-off: a briefly-stale index may only reject at the final step. Validate with a real order.
fast_stock_syncFast Stock Sync. On an order/refund/inventory save, patch only the stock fields of affected OS docs instead of reprojecting the whole product. Runs after the response — no shopper latency. Falls back to a full reproject if a doc isn't fully present.
The three default to 0 by design: the master OR each flag turns a feature on, so leaving them at 0 is what lets the master switch cleanly enable and disable the whole bundle.

Configurable Line-Item Name

SelectDefault: ParentStore-level
fastmagento/cart/configurable_line_name

Which name to show for a configurable product on cart / mini-cart / checkout. Display only — it does not change price or the placed-order line data.

ParentConfigurable name — Magento default. e.g. "Keira Banded Bra" with Color / Size beneath. (default)
ChildSimple (variant) name — the specific purchased variant's own name.

5 · Cache Warmup

fastmagento/cache/*

Popular Search Terms

TextareaDefault: blankStore-level
fastmagento/cache/popular_searches

A comma-separated list of your highest-traffic search terms. The scheduled cache-warmup cron pre-renders these result pages so the first real shopper of the day hits a warm cache instead of a cold render.

Examplea-arm, rock slider, light bar, rzr cage, tie rod
Warmed by the fastmagento_cache_warmup cron. Keep the list short and genuinely popular — warming rarely-used terms just wastes cache.

6 · Extension Efficiency Monitor

fastmagento/efficiency/*  ·  Global only   Profiles how much database work each third-party extension adds to the hot paths (indexing, product pages, category grids, search, logged-in customer data). View it under FastMagento > Extension Efficiency.

Run Scan on a Schedule

Yes / NoDefault: NoGlobal only
fastmagento/efficiency/cron_enabled  ·  …/cron_expr

Off by default. When on, a scan runs automatically on the schedule and refreshes the monitor. The schedule is a standard cron expression (default 0 3 * * 0 = Sundays 3:00 AM).

A scan briefly enables query logging to attribute SQL to modules — so it's opt-in. Don't overlap a full reindex. You can always run one on demand from the admin page or with bin/magento fastmagento:efficiency:scan.

Sample Size

NumberDefault: 50Global only
fastmagento/efficiency/sample_size

Products / rows profiled per scenario. Higher = steadier averages but a slower scan.

7 · Advanced (config-only)

These have no admin screen — set them via app/etc/config.php, env.php, or bin/magento config:set. Defaults are correct for almost everyone.

Attribute-Option Pagination

Flag + NumberDefault: On · 50 per pageStore-level
fastmagento/attribute_pagination/enabled  ·  …/page_size

Replaces Magento's native "Manage Options" / swatch grid — which loads and re-saves the entire option set and buckles past a few thousand options — with a paginated, per-row CRUD manager.

Leave On unless you specifically need the native grid. Only matters for attributes with very large option sets (e.g. thousands of colors/sizes).

Attribute-Option Index Suffix

TextDefault: attribute_optionsStore-level
fastmagento/indexing/opensearch_option_index_prefix

Suffix for the attribute-option index (→ magento2_attribute_options). Same convention as the product/category suffixes; rarely changed.

Paths & CLI cheat-sheet

# Set any value from the CLI (great for CI / multi-store)
bin/magento config:set fastmagento/search/search_operator all
bin/magento config:set --scope=stores --scope-code=default fastmagento/cart/enable_fast_checkout 1

# After changing searchable attributes / AI keywords
bin/magento fastmagento:search-keywords:generate  # optional: build the AI keyword layer
bin/magento indexer:reindex catalogsearch_fulltext fastmagento_product fastmagento_category

# Efficiency monitor on demand
bin/magento fastmagento:efficiency:scan --sample=50

# Flush after config changes
bin/magento cache:flush

FastMagento — Settings Reference

Admin location: Stores > Configuration > FastMagento Settings. Config paths shown on each card also work via bin/magento config:set, app/etc/config.php and env.php. All features degrade safely to native Magento on any miss or outage.
